# Data Quality Rules

## 처리 원칙

2026-09-28에 규칙 엔진 1.0을 구현한 뒤 파서 결함을 개선해 현재 규칙 버전은 1.1입니다. Phase 4는 JSON 보고서, Phase 5는 DB 결과 적재, Phase 6은 DAG 연결을 구현했습니다. Phase 7의 배치 게이트 정책 1.0은 전체 격리율 > 5%일 때 실패입니다. 레코드 규칙 버전과 게이트 정책 버전은 별개입니다.

| ID | 이름 | 초기 판정 | 처리 |
|---|---|---|---|
| DQ001 | PRODUCT_ID_REQUIRED | `product_id`가 NULL 또는 공백 | 격리 |
| DQ002 | PRODUCT_ID_FORMAT | 값이 존재하지만 `^P[0-9]{6,}$` 형식과 불일치 | 격리 |
| DQ003 | DUPLICATE_PRODUCT_ID | 한 배치 안에서 정규화한 비어 있지 않은 `product_id`가 중복 | 그룹의 모든 행 격리 |
| DQ004 | CATEGORY_ALLOWED | `category`가 NULL/공백이거나 `TUMBLER`, `BAG`, `SHOES`, `LAMP`에 없음 | 격리 |
| DQ005 | ATTRIBUTE_REQUIRED | `extracted_attribute`가 NULL | 격리 |
| DQ006 | ATTRIBUTE_NOT_EMPTY | 속성값이 공백 문자열 | 격리 |
| DQ007 | ATTRIBUTE_HAS_CONTENT | 비어 있지 않은 속성에 Unicode 글자나 숫자가 하나도 없음 | 격리 |
| DQ008 | ATTRIBUTE_LENGTH_LIMIT | 정규화 후 속성값이 초기 상한 200자를 초과 | 격리 |
| DQ009 | OCR_TEXT_MISMATCH_SIGNAL | 정규화하고 대소문자를 구분하지 않은 OCR과 원문이 다름 | WARNING 기록; 단독이면 PASS |
| DQ010 | ATTRIBUTE_EVIDENCE_CANDIDATE | 추출 속성의 지원 숫자·단위 쌍이 원문에 없음 | ERROR로 격리 후보; 환각 확정 아님 |

## 구현한 정규화와 경계

- Unicode NFKC 후 연속 공백을 한 칸으로 만들고 양끝 공백을 제거합니다. ID·카테고리는 대문자로 정규화합니다. RAW 값은 변경하지 않습니다.
- 누락 ID에는 DQ001만, 존재하는 형식 오류 ID에는 DQ002를 적용합니다. 누락 ID끼리는 중복으로 세지 않습니다. 형식 오류 ID라도 같은 비어 있지 않은 값이 반복되면 DQ003도 기록합니다.
- 속성 NULL은 DQ005, 빈 문자열·공백은 DQ006입니다. DQ007은 비어 있지 않은 값에만 적용합니다. 한 행에 서로 다른 문제는 모두 기록합니다.
- DQ008은 정규화한 Python 문자열 길이 기준입니다. 200자는 허용하고 201자는 ERROR입니다. 화면에 보이는 글자 수와 다를 수 있습니다.
- DQ009는 NULL과 빈 문자열을 비교상 같은 값으로 취급합니다. 문장부호는 유지합니다. WARNING 행 수도 보고하지만 해당 행이 다른 ERROR를 가지면 격리 대상입니다.
- DQ010은 `ml`, `l`, `mm`, `cm`, `w`, `g`, `kg` 단위와 정수·소수·부호·올바른 천 단위 쉼표를 비교합니다. `1,500ml`는 1500ml입니다. 단위 대소문자, `500 ml` 공백, `500.0ml` 표현 차이와 단위 뒤 한글 접미사를 허용합니다. 단위 환산은 하지 않아 `1L`와 `1000ml`는 서로 다릅니다. 지수 표기·잘못된 쉼표처럼 발견한 숫자 후보를 해석할 수 없으면 DQ010 ERROR를 기록합니다. 지원 토큰이 전혀 없으면 `evidence_status=NO_SUPPORTED_QUANTITY`이며 의미적 근거 검증을 수행한 것이 아닙니다. 원문이 없는데 속성에 지원 토큰이 있으면 근거 부족 후보로 표시합니다. 자세한 한계는 [개선 기록](PHASE4_REMEDIATION.md)에 있습니다.
- PASS는 구현한 ERROR 규칙이 없다는 뜻입니다. 모든 의미적 품질이 보장된다는 뜻은 아닙니다.

실행 방법과 배치 결과: [Phase 4 구현 기록](PHASE4_QUALITY_ENGINE.md).

## 중요 해석

- DQ009의 텍스트 불일치는 그 자체로 OCR 오류의 증거가 아닙니다. 정규화 후 단순 비교 결과라는 한계를 문서화합니다.
- DQ010은 의미 검증기가 아닙니다. 가상 데이터에서 후보를 표시하는 제한된 규칙이며, 실제 의미적 근거 판정으로 설명하지 않습니다.
- `created_at` 결측 등 추가 규칙은 첫 구현 이후 필요성과 영향을 확인해 추가합니다.
- 허용 카테고리 목록과 ID 정규식은 Phase 2 생성 데이터에 맞춰 정했습니다. 특수문자와 경계값 정책은 위 구현 기준을 따릅니다.
- 품질 비율 임계치는 레코드 규칙과 분리된 배치 수준 정책입니다.

## 배치 품질 게이트 — 정책 1.0

Phase 7에서 **배치 전체 격리 행 수 / 전체 입력 행 수 > 5%**이면 FAIL로 확정·구현했습니다. 정확히 5%는 PASS이며 반올림한 표시 비율로 비교하지 않습니다. 기본 합성 배치 4.1%는 실제 DAG에서 PASS였습니다. 이 기준은 학습용 고정 기준이며 운영 SLA나 통계적 기준은 아닙니다. 품질 저하 배치 실패 시연은 Phase 8에 남습니다.

결과·마트·판정 이력을 커밋한 뒤 마지막 태스크가 실패합니다. NULL 속성 비율은 RAW NULL 속성 행 / 전체 입력 행으로 기록하지만 별도의 NULL/그룹 임계치는 적용하지 않습니다. 집계 날짜·차원·재실행 정책은 [Phase 7](PHASE7_QUALITY_MART.md)에 있습니다.

## 규칙 확장 기준

새 규칙을 추가할 때 `rule_id`, 목적, 대상 필드, 판정 조건, severity, 처리 정책, 예시 입력/결과, 한계를 이 문서에 함께 추가하고 규칙 버전을 올립니다.
