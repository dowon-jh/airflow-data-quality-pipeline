## 4. 운영 의미와 한계

RAW는 원본을 보존합니다. 최신 CLEAN·QUARANTINE·이슈·마트는 배치별 교체하고 성공 처리 요약·규칙 버전·게이트 판정은 이력으로 남깁니다. 전체 과거 결과 행이나 마트의 시점별 스냅샷을 DB에 누적하는 기능은 없습니다.

게이트 FAIL은 저장된 결과를 삭제하지 않습니다. 소비 시 최신 처리 UUID에 대응하는 PASS를 확인해야 합니다. 자동 외부 배포·후속 시스템 사용 승인까지 구현한 것은 아닙니다. 5%는 학습용 선택이며 실무 SLA, 그룹별/NULL 비율 차단 기준은 별도 설계 대상입니다.

DQ010은 제한된 숫자·단위 근거 후보 검사입니다. 지원 밖 표현, 단위 환산, 의미 전체 검증을 포괄하지 않으며 실제 LLM 능력이나 환각 확정 판정을 보여주는 프로젝트는 아닙니다.

제한 DB 계정·비밀파일·loopback UI·DB 포트 미게시·읽기 전용 코드 mount를 적용했습니다. 로컬 standalone 구성이며 운영용 인증·TLS·백업 복원·CVE/침투 검증까지 완료했다고 주장하지 않습니다.

실제 timeout 소진, 대용량 부하, DB 강제 종료 crash recovery, 복구 명령 자체 실패, 모든 규칙 경계의 회귀 테스트, 새 PC 설치는 미검증입니다. Phase 9 문서 작업 당시에는 읽기 전용 확인만 수행했고, 이후 사용자 요청으로 같은 PC의 빈 볼륨 초기 준비·기본 DAG 실행을 재현했습니다.

Phase 9 당시 Git 커밋·공개 원격 저장소는 없었습니다. 이후 GitHub 공개용 정리 대상은 [airflow-data-quality-pipeline](https://github.com/dowon-jh/airflow-data-quality-pipeline)입니다. 원본 실행 증거는 Git ignore 대상이므로 별도로 보관하며 공개용 [검증 요약](evidence/verification-summary.json)을 제공합니다. 비밀번호는 문서에 기록하지 않았습니다.
