# 프로젝트 기획안 대비 수행 검토

검토일: 2026-09-28  
기준 문서: `AIRFLOW_PROJECT_BRIEF.md`, `ROADMAP.md`, 설계·결정 기록  
근거: 현재 코드·파일 목록·생성 매니페스트·검사 보고서와 실제 PostgreSQL 조회

## 1. 종합 판단

후속 상태: 이 문서는 Phase 5 구현 전 비교 기록입니다. 이후 Phase 5~7 구현과 Phase 8 장애·재실행·복구 시연을 수행했습니다. 최신 증거는 [Phase 8](PHASE8_FAILURE_RECOVERY.md)에 있습니다. 다음은 Phase 9 문서 마무리이며 아래 표의 상태는 검토 당시 기록입니다.

**현재까지의 핵심 범위와 진행 순서는 기획에 맞습니다.** 가상 데이터 → RAW 보존 → 규칙 검사까지 구현했고, LLM 연동·외부 도구로 범위를 확장하지 않았습니다. 검토 중 발견한 결함과 보안 항목을 개선한 것도 기존 흐름의 신뢰성을 높이는 선행 작업입니다.

현재 위치는 **Phase 4 구현 및 후속 개선까지**입니다. 다음은 Phase 5 CLEAN·QUARANTINE 적재입니다. 프로젝트 전체 완료 기준은 아직 충족하지 않았으며, Airflow 자동화·품질 마트·전체 장애 복구 검증은 남아 있습니다.

일정과 단계별 공수 기준이 없어 일정 준수나 지연 여부는 판단하지 않았습니다. 단계 수만으로 완료율을 계산하지 않았습니다.

## 2. 단계별 기획 대비 상태

| 단계 | 기획 목표 | 확인한 구현·근거 | 판단 |
|---|---|---|---|
| Phase 0 | 범위·계층·규칙·실패 기준 설계 | 기획·아키텍처·모델·규칙·결정·장애 문서 존재 | 핵심 설계 작성; 일부 범위·정책 정리 필요 |
| Phase 1 | Airflow·PostgreSQL 로컬 실행과 데이터 보존 | Compose 구성, 로그인·DB 접속 실행 기록, 별도 volume | 현재 로컬 환경에서 충족; 새 PC 재현 검증은 미수행 |
| Phase 2 | 재현 가능한 정상·오류 데이터 생성 | 옵션 기반 생성기, 라벨 분리, seed·버전·SHA 매니페스트 | 핵심 범위 충족; 초기 외국어 노이즈 항목은 미정리 |
| Phase 3 | RAW 계층·배치 식별·오류 원본 보존 | RAW 테이블 2개, 두 배치 2,000행, 해시·건수 기반 재적재 정책 | 현재 단계 목표 충족 |
| Phase 4 | 10개 규칙과 식별 가능한 결과 | 규칙 1.1, 행별 이슈 JSON, 기본 배치 및 일부 경계 사례 실행 | 구현 목표 충족; 전체 경계·조합 검증을 완료한 것은 아님 |
| Phase 5 | 정상·오류 DB 분리 및 재실행 멱등성 | schema만 있고 결과 테이블·적재 코드 없음 | 다음 구현 단계 |
| Phase 6 | DAG 실행·의존성·로그·재시도 | `airflow/dags/`에는 `.gitkeep`만 있음 | 미구현; 서비스 기동과 DAG 구현은 구분 |
| Phase 7 | 차원별 품질 마트·임계치 차단 | 배치 JSON 요약만 존재, mart 테이블 없음 | 미구현; JSON 집계는 마트의 대체 완료물이 아님 |
| Phase 8 | 전체 장애·복구·재실행 시연 | 초기 오류 해결·품질 오판 재현·권한 검토 기록 | 일부 선행 경험만 수행; 단계 전체는 미완료 |
| Phase 9 | 다른 사람이 실행 가능한 완성 문서 | 현재까지 문서는 축적됨 | 진행 중; 전체 파이프라인 완성 후 재현 검증 필요 |

Phase 5 이후 미구현은 현재 순서에 따른 남은 작업입니다. 이미 구현한 단계에서 목표와 다른 문제, 앞으로 결정해야 할 정책, 아직 순서가 오지 않은 작업을 구분했습니다.

## 3. 실제 확인한 상태

이번 검토에서는 기존 데이터·서비스·권한을 변경하지 않고 DB를 조회했습니다.

- `raw`, `clean`, `quarantine`, `mart` schema 4개 존재.
- 실제 프로젝트 테이블은 `raw.ai_product_output`, `raw.ingest_batch` 2개뿐.
- `batch-208ca532eb1f`, `batch-a2ebfbe5e814` 각각 1,000행, RAW 총 2,000행.
- RAW의 `model_version`은 현재 1종. 두 배치는 모델 품질 비교 배치가 아니라 생성기 수정 전·후 배치.
- 저장된 검사 보고서의 규칙 버전은 1.1, 통과 대상 959행·격리 대상 41행·경고 3행·이슈 44개.
- 결과 JSON에는 규칙별 집계와 행별 판정이 있지만 결과 DB 적재는 없음.
- Git에는 아직 커밋이 없어 버전 복구 기준점은 없음.

## 6. 기획 대비 보완할 점

### A. 초기 후보 범위와 확정 범위를 연결해야 함

초기 기획에는 **외국어 노이즈**와 **입력 급감**이 있습니다. 현재 10개 규칙·생성 오류 목록에는 외국어 노이즈의 명시적 판정이 없으며, 입력 급감의 비교 기준과 처리 기준도 없습니다.

이 항목을 첫 버전에 넣을지 후속으로 미룰지 결정 기록에 남겨야 합니다. 외국어라는 이유만으로 오류로 간주하는 규칙을 임의로 추가할 근거는 없습니다. 입력 급감은 Phase 7의 배치 정책 설계에서 기준을 정할 수 있습니다.

### B. 빈 배치의 문서와 코드가 아직 일치하지 않음

결정 기록 D-008과 장애 문서는 빈 배치 처리 정책을 미정으로 적었습니다. 하지만 현재 RAW 적재기와 DQ 엔진은 빈 입력을 오류로 거부합니다.

현재 동작을 첫 버전 정책으로 확정할지, 데이터 없음 상태를 별도로 허용할지 문서로 정리해야 합니다. 이번 검토에서는 정책을 임의로 바꾸지 않았습니다.

### C. Phase 5에서 결과 키·버전·실행 정보를 먼저 확정해야 함

현재 결과 테이블 초안은 `(batch_id, source_record_id)` 중심이고, 새 규칙 버전으로 같은 RAW를 재평가하는 정책도 있습니다. 아래 결정을 먼저 해야 DB 설계의 재작업을 줄일 수 있습니다.

- 현재 결과를 안전하게 교체할지, 규칙/실행별 결과 이력까지 보관할지.
- 모든 결과와 이슈에 규칙 버전·처리 실행 식별자를 어떻게 남길지. DAG 구현 전 수동 실행도 식별할 수 있어야 함.
- CLEAN·QUARANTINE·이슈·처리 이력을 한 트랜잭션으로 갱신하고, 같은 배치 동시 실행을 어떻게 막을지.
- PASS 행의 WARNING은 RAW FK로 저장해 격리 행 전용 FK와 충돌하지 않게 할지. 이 방향은 이미 문서에 반영됨.

### D. Phase 7의 지표·임계치 정책은 아직 초안

5% 격리율은 구현된 품질 게이트가 아닙니다. 모델별 NULL 증가 시나리오도 실제 적재·차단까지 실행하지 않았습니다. `created_at`은 RAW에서 NULL을 허용하므로 향후 집계 날짜에 생성 시각·적재 시각·처리 시각 중 무엇을 사용할지도 정해야 합니다.

DB·스키마 실패는 처리 중단으로, 품질 임계치 실패는 결과·지표를 먼저 보존하고 최종 게이트 실패로 처리하도록 오류 종류별 저장 순서도 명확히 해야 합니다.

### E. 구현 완료와 검증 완료를 구분해야 함

검토 스크립트로 일부 경계값과 오판 사례를 확인했지만 전체 규칙의 모든 경계·다중 오류 조합, 준비 스크립트 실제 실패 복구, 새 PC 설치는 검증하지 않았습니다. 초기 기획은 pytest를 선택 도구로 제시했으므로 특정 도구 미사용 자체가 기획 위반은 아닙니다. 다만 최종 장애·복구 완료를 주장하려면 시연 증거가 필요합니다.

현재 Git 미커밋 상태도 이후 단계의 수정·복구 추적을 위해 보완할 항목입니다. 이번 검토에서 커밋을 생성하지는 않았습니다.

## 7. 다음 작업 권장 순서

1. Phase 5의 결과 교체/이력 정책, 처리 실행 ID, 트랜잭션 경계를 확정하고 구현.
2. CLEAN·QUARANTINE·이슈 실제 건수와 결과 계층 재실행 동작을 확인.
3. Phase 6에서 기존 Python 로직을 DAG로 연결.
4. Phase 7에서 품질 마트·날짜 기준·모델 품질 저하 배치·임계치 정책을 구현.
5. Phase 8에서 전체 장애·복구 시연을 수행하고 Phase 9의 최종 문서를 정리.

외국어 노이즈·입력 급감·빈 배치 범위는 관련 단계 전 결정 기록에 반영합니다. 현재의 보안·경계 사례 보완을 반복 확장하기보다, 남은 핵심 흐름을 순서대로 연결하는 것이 기획 목표에 가깝습니다.

## 검토 결과 한 문장

**기획의 범위와 순서에 맞게 기반과 품질 엔진을 구현하고 있으며, 다음 핵심 성과는 실제 CLEAN·QUARANTINE 적재입니다. Airflow 자동화·품질 지표·전체 장애 검증까지 연결해야 기획의 최종 목표를 충족합니다.**
