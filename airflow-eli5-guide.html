ELI5 · 신입 온보딩

Airflow는 일을 대신하는 로봇이 아니라, 일을 잘 시키는 관제탑입니다.

매일 같은 시간에 데이터를 가져오고, 순서대로 처리하고, 실패하면 다시 시키고, 결과를 확인하는 방법을 배웁니다.

🗺️
DAG = 작업 지도

무슨 일을 어떤 순서로 할지 그린 설계도

🧩
Task = 한 가지 일

가져오기, 검사하기, 저장하기처럼 작게 나눈 작업

🧑‍✈️
Scheduler = 배차 담당자

언제 실행할지 결정하고 일을 배정하는 역할

01 · 딱 하나의 그림

Airflow를 택배 회사처럼 생각해보세요

Airflow는 데이터를 저장하는 곳이 아닙니다. “이 일을 먼저 하고, 끝나면 다음 일을 하라”는 약속을 지키는 관리자입니다.

📦

데이터 파이프라인 = 택배 흐름

상품을 접수하고 → 분류하고 → 배송하고 → 도착 확인을 합니다. 중간 단계가 실패하면 어디서 멈췄는지 알아야 합니다.

🎛️

Airflow = 관제탑

직접 택배를 보관하지 않고, 각 담당자에게 일을 시키고 상태를 기록합니다.

1. 추출원천 데이터 가져오기
→
2. 검증문제 있는지 검사
→
3. 적재DB에 저장
기억할 문장: Airflow가 데이터를 “들고 있는” 것이 아니라, 데이터 일을 “순서대로 실행하고 감시”합니다.
02 · 기본 단어

실무에서 매일 듣게 될 9가지

아래 단어를 알면 Airflow 화면과 팀 대화의 절반이 이해됩니다.

설계도

DAG

Directed Acyclic Graph. 작업과 순서를 적은 지도입니다. 같은 길을 무한히 돌지 않도록 순환이 없어야 합니다.

“전체 작업의 지도”
작은 일

Task

하나의 독립적인 작업입니다. 예: CSV 읽기, SQL 실행, 품질 검사, 결과 저장.

“지도 안의 한 칸”
실행 방법

Operator

Task를 어떤 방식으로 실행할지 정한 도구입니다. Python 함수 실행, SQL 실행, Bash 실행 등이 있습니다.

“일을 하는 도구의 종류”
한 번의 실행

DAG Run

스케줄에 따라 DAG 전체가 한 번 실행된 기록입니다. 오늘 배치 1회가 하나의 DAG Run입니다.

“오늘 한 번의 배차”
결정자

Scheduler

실행할 시간이 되었는지 보고, 어떤 Task를 실행할지 결정합니다.

“언제 출발시킬지 정함”
실행자

Worker

Scheduler의 지시를 받아 실제 Python, SQL, Bash 등을 실행합니다.

“실제로 손발을 움직임”
작은 메모

XCom

Task끼리 작은 값 하나를 전달하는 메모입니다. 대용량 데이터는 DB나 파일 저장소에 두고 XCom에는 경로만 전달합니다.

“쪽지이지 창고가 아님”
접속 정보

Connection / Variable

DB 접속 정보나 환경별 설정을 코드 밖에서 관리합니다. 비밀번호를 DAG 코드에 하드코딩하지 않습니다.

“비밀과 설정은 금고에”
기록

Log / Metadata DB

로그는 실행 과정의 일기이고, Metadata DB는 Task 상태와 DAG Run 상태를 기록하는 장부입니다.

“문제가 생기면 기록부터 확인”
03 · 실제로 무슨 일이 일어나는가

실행 흐름은 이렇게 움직입니다

사람이 버튼을 누르거나 스케줄 시간이 되면, Airflow는 아래 순서로 움직입니다.

🧑‍💻1. 요청 또는 스케줄“오늘 데이터 처리해!”
🧭2. Scheduler 판단의존성이 끝났는지 확인
⚙️3. Worker 실행Task를 실제로 수행

의존성(Dependency)

추출이 끝나야 검증을 시작하는 식으로 작업 사이의 순서를 정합니다. Airflow에서는 보통 “upstream이 끝난 뒤 downstream이 실행된다”고 말합니다.

상태(Status)

Task는 보통 queued → running → success로 갑니다. 실패하면 failed가 되고, 재시도 설정이 있으면 up_for_retry가 됩니다.

04 · 코드 모양 익히기

아래 코드는 “작업 지도를 그리는 법”입니다

이 코드는 개념을 보여주는 작은 예시입니다. 핵심은 함수 내용보다 Task 사이의 순서입니다.

# 개념용 Airflow DAG 예시 from airflow import DAG from airflow.operators.python import PythonOperator from datetime import datetime def extract(): # 원천 데이터 가져오기 pass def validate(): # NULL, 중복, 형식 검사 pass with DAG("ai_output_quality_pipeline", start_date=datetime(2026, 1, 1), schedule="@daily", catchup=False) as dag: extract_task = PythonOperator(task_id="extract_raw_data", python_callable=extract) validate_task = PythonOperator(task_id="validate_schema", python_callable=validate) extract_task >> validate_task # “extract가 끝난 뒤 validate를 실행하라”
코드에서 특히 봐야 할 부분
  • dag: 전체 작업 지도의 이름입니다.
  • task_id: Airflow UI에서 보이는 작업의 고유 이름입니다.
  • python_callable: Task가 실행할 Python 함수입니다.
  • >>: 왼쪽 작업이 끝난 뒤 오른쪽 작업을 실행한다는 뜻입니다.
  • 실무에서는 함수 안에 대량 처리를 넣기 전에 재실행해도 안전한지 먼저 생각합니다.
05 · 신입 필수 지식

실무에서 반드시 챙길 8가지

스케줄 시간 ≠ 처리 데이터 시간

새벽 1시에 실행되어도 어제 하루 데이터를 처리할 수 있습니다. 실행 시각과 대상 데이터 구간을 구분하세요.

재시도는 공짜가 아니다

Task가 다시 실행되어도 중복 적재가 생기지 않도록 Idempotency를 설계해야 합니다.

Task는 작고 명확하게

추출, 변환, 적재를 한 Task에 모두 넣기보다 실패 지점을 찾기 쉽게 적절히 나눕니다.

XCom에 큰 데이터를 넣지 않기

큰 DataFrame이나 파일 본문은 DB·오브젝트 스토리지에 두고 경로·ID만 전달합니다.

비밀정보를 코드에 쓰지 않기

비밀번호와 토큰은 Connection, Secret Backend, 환경 설정으로 관리합니다.

로그가 곧 첫 번째 증거

실패하면 추측하지 말고 Task 로그, 입력 건수, SQL 결과, upstream 상태를 순서대로 확인합니다.

데이터 품질 오류와 시스템 장애 구분

일부 레코드 오류는 격리하고, DB 연결 실패나 스키마 변경은 파이프라인을 중단할 수 있습니다.

스케줄보다 재현성이 먼저

수동 실행, 재실행, 백필을 해도 같은 입력에 예측 가능한 결과가 나와야 합니다.

06 · 이 프로젝트에 적용하기

AI 데이터 품질 파이프라인에서는 이렇게 생각합니다

소수의 나쁜 레코드와 전체 파이프라인의 위험을 같은 방식으로 처리하지 않습니다.

Record-level Error
문제 레코드만 Quarantine
→
Pipeline-level Error
임계치 초과 시 Task Fail
계속 처리

NULL 한 건

해당 레코드는 Quarantine으로 보내고, 정상 레코드는 Clean Layer로 계속 보냅니다.

중단 검토

NULL 비율 30%

데이터 전체가 믿기 어려울 수 있으므로 품질 검사를 실패시키고 후속 적재를 막습니다.

관찰

Hallucination Candidate

원문에서 근거를 찾기 어려운 값은 확정 오류가 아닌 추가 검수 후보로 기록합니다.

07 · 초보자가 자주 하는 실수

이것만 피해도 절반은 성공입니다

실수 1

DAG 파일 안에서 바로 데이터 처리

DAG 파일은 지도만 그려야 합니다. 무거운 API 호출이나 DB 처리는 Task가 실행될 때 하세요.

실수 2

Task 하나에 모든 일을 넣기

실패 위치가 보이지 않습니다. 추출·검증·적재처럼 관찰 가능한 단위로 나누세요.

실수 3

재실행하면 중복되는 적재

실패한 Task를 다시 실행할 수 있도록 키, 파티션, UPSERT, 트랜잭션을 설계하세요.

실수 4

로그 없이 “Airflow가 이상해요”라고 말하기

어느 DAG Run의 어느 Task가 어떤 입력으로 실패했는지부터 확인하고 공유하세요.
